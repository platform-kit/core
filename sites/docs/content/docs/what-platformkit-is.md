## What it is

PlatformKit is a full-stack TypeScript framework for building and deploying a complete online business: content and publishing, payments, subscriptions and memberships, a store, bookings and video sessions, forms, email marketing, customer support, community, analytics and AI assistants. Each area is a module a site switches on, and the engine, its default theme and its admin ship as one package.

A site chooses modules in `platformkit.config.js` and supplies its own content, business rules, and visual design. For example, a publisher can enable books, print sales, memberships, and email; a practice can enable bookings, paid sessions, and member chat. These are configurations of one platform, not separate product forks.

## What comes in the platform

- **Kit (`platformkit`):** content processing, the CLI, build and deployment tools, database declarations, APIs, and shared services such as checkout and messaging.
- **Theme (`platformkit/theme`):** the public pages, reader and admin interfaces, components, and styles.
- **Site:** the configuration and content that select the modules, set the brand and policies, and add site-specific components, routes, data, or admin screens.

The demo site enables modules to show how they work together. The docs site disables the application modules and serves documentation without sign-in.

## How sites are configured

The site's configuration determines which routes, navigation items, admin screens, build steps, and deployment requirements exist. Turning off a module removes the surfaces it owns. Site code can replace a named theme component without copying the theme, and site strings can override the theme's defaults.

The platform keeps a few conventions consistent across modules:

- **Content is authored as records.** A page, product, book, or email has a defined file or row as its source of truth.
- **The database is declared.** Schema files describe the intended tables; the migration planner compares them with the database and blocks destructive changes unless explicitly allowed.
- **Drafts are not public.** Unpublished records remain editable but are excluded from public routes, search, and build output.
- **Interface copy is editable.** Reader- and admin-facing words live in markdown string files, not component templates.
- **Forms edit structured values.** The admin presents fields and controls instead of asking editors to type YAML or another file grammar.
- **Deployment checks run first.** Before deploying, PlatformKit checks that enabled features have the required credentials and that mock integrations are off.

## Where content lives

File-backed sites keep their records in the site's `content/` directory. In cloud mode, Supabase stores a draft and a published version of each record. Publishing makes the draft live; if the site has a repository in its publish cycle, it also commits the change and triggers a rebuild. A cloud deployment without a repository serves the published database records directly.

The admin uses the same editing workflow in local development and in production when row-backed content is enabled. Static deployments do not include a production admin or authentication. See [The three deployment shapes](/content/docs/building-a-site/deployment-modes) for the full comparison.

## Example site configurations

- **Documentation site:** enable docs, disable account and commerce modules, and deploy static files.
- **Online shop:** enable the store and configure payment and shipping; leave the book library and community modules off if they are not needed.
- **Paid publication:** combine books, memberships, print editions, and email campaigns.
- **Member community:** combine memberships, spaces, and the support desk; use membership tiers to control access where required.
- **Booking practice:** enable sessions and configure the scheduler, access rules, and payment method for each appointment.
- **Directory:** define a content model for each listing type, then publish model entries through the site's pages.
- **Assessment product:** register an instrument with the site's questions, scoring rules, and results copy.
