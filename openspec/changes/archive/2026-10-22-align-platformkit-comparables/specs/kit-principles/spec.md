# Spec Delta

## MODIFIED Requirements

### Requirement: Every comparable's core job is a module with a switch

Each row of the comparables table SHALL be carried by a named module that works out of the box, can be switched off whole, and documents in its spec what it deliberately does not do that the comparable does. The Typeform row SHALL read: **instead of** Typeform, SurveyMonkey, forms.md — **the kit's module** forms, and instrument over it — **what it does** a general-use form builder: a form is a forms.md document (its field kinds, slides, logic jumps, bindings), run by the kit's own runner in the site's design, written by a builder that never shows the grammar, with the backend forms.md lacks — every answer a row as it is given, files in a bucket, a webhook, responses and analytics in the admin — on its own page, embedded, or on a landing page; and, over it, the quiz-scoring / IRT instrument: screens drawn from a bank, scored by the site's registered graders — the forms served over Typeform's own Create (read), Responses, Webhooks and Insights APIs with keys, so Typeform's client and embed work with the host swapped. `instrument` SHALL require `forms`. The table SHALL carry a Contentful row, after the WordPress row, reading: **instead of** Contentful, Sanity, Strapi — **the kit's module** content models, content API — **what it does** content types defined in the admin as fields with kinds and rules; entries as markdown with frontmatter, edited as forms; delivered as data, plain pages, static JSON or a landing section, as each model says — and served over Contentful's own Delivery, Preview, GraphQL, Sync and Images APIs — and, in cloud mode, written through its Management API with its webhooks — with keys, so a Contentful client works with the host swapped, reading and writing. The Shopify row SHALL read: **instead of** Shopify, BigCommerce, Gumroad — **the kit's module** store — **what it does** products, a bag, checkout with shipping chosen first, guest checkout, downloads, orders — the store served over Shopify's own Storefront API (products, collections, the cart, a checkout url into the site's bag) with a public token, so a headless storefront and Shopify's storefront client work with the domain swapped. The Crisp row SHALL read: **instead of** Crisp, Chatwoot, Intercom — **the kit's module** support chat, coaching chat — **what it does** an embedded chat for guests and readers with an inbox, prompts, escalation; a members' chat with coaches — the desk served over Chatwoot's own Client and Application APIs with webhooks and keys, and Chatwoot's website snippet mounting the site's widget on any page, so anything written for Chatwoot works with the base changed. The Elementor row SHALL read: **instead of** Elementor, Plasmic, Builder.io — **the kit's module** page builder, experiments — **what it does** landing pages from a catalogue of some forty sections with schemas and layouts — openers (an announcement, a hero that takes any visual, a marquee), content (features, a split, a bento, steps, a showcase, before/after, a carousel, tabs, a gallery, a video, prose, a timeline, a divider), proof (logos, stats, testimonials, a quote, a comparison, an FAQ, integrations), commerce (pricing, perks, products, a spotlight, collections), people (a team, a newsletter, a contact block, a form), the site's own data (articles, a model's entries), closers (a call to action, a countdown, the close, a footer) — each a form in the admin with one look fold (tone, glow, ground, spacing, width, reveal), drawn in the site's look; A/B tests as their own records. The Calendly row SHALL read: **instead of** Calendly, Acuity, cal.com — **the kit's module** sessions — **what it does** booking inside the app on the site's own calendar (a coach's hours, seats, notice, reminders and invitations) or on cal.com's engine, under the site's own judge of what a plan allows — the sessions served over cal.com's own API v2 with webhooks and keys, so cal.com's embed and anything written against its API work with the host swapped. The Zoom row SHALL read: **instead of** Zoom, Google Meet, Daily — **the kit's module** sessions, spaces — **what it does** a video room on the site for a booked call or a channel's huddle — on LiveKit where the site has an account, recorded into the site's own storage, and browser to browser with no account and nothing to configure where it has none; or a link to a room elsewhere. The table SHALL carry a Slack row, reading: **instead of** Slack, Microsoft Teams, Discord — **the kit's module** spaces — **what it does** the business's own chat: spaces whose membership is a role or a tier, channels read as a stream or a forum, direct messages, threads, mentions that decide the notification, search, huddles, a channel that may be end-to-end encrypted, and operations channels the platform writes into — an order, a failed print job, an escalation are the database's own messages, not an integration. The prior Circle row (**Circle.so, Mighty Networks, Discourse**) SHALL be replaced with a row reading: **instead of** Circle.so, Mighty Networks, Skool, Discourse — **the kit's module** spaces, network, memberships — **what it does** a community for the site's members: the tier that was bought is the membership of the space, channels per book, topic or cohort read as chat, a forum or a feed, the space's feed pinnable in any atproto client, and a member's card showing what they have read, scored and bought. The table SHALL also carry a Bluesky, Mastodon row, reading: **instead of** Bluesky, Mastodon — **the kit's module** network — **what it does** the site's own social network: every member a page, follows, a timeline, posts with likes, reposts, replies and quotes, each post to everyone, to the site's own people or to a space's members — closed to the site's people by default, joined to Bluesky's network by the site's switch and each member's consent — the whole of it served as an atproto server and app view, so Bluesky's app and any atproto client sign in with the host swapped.

#### Scenario: a module's non-goals

- **WHEN** a kit spec is read
- **THEN** it names its comparable and the things it leaves to that comparable on purpose

Verified by: `openspec validate` plus reading; phase 0 adds the section to every kit spec

#### Scenario: the table and the overview agree

- **WHEN** the Typeform, Contentful, Shopify, Crisp, Elementor, Calendly, Zoom, Circle and Bluesky/Mastodon rows are read in the spec's table and in the comparison document (`docs/COMPETITORS.md`, the docs site's copy)
- **THEN** they say the same thing in the first three columns, and `docs-check.mjs` holds them equal

Verified by: `node packages/kit/build/docs-check.mjs` in `npm test`
